# Accessibility (A11Y)

Concord targets **WCAG 2.2 Level AA** on every dashboard screen. Compliance is enforced automatically by an axe-core scan that runs through Playwright on every PR.

## Target

- WCAG 2.1 Level A and AA
- WCAG 2.2 Level A and AA
- AAA findings are surfaced as warnings only — they do not fail the build.

## How to run the scan locally

Prerequisites: Node.js, the dashboard servable as a static site, and Playwright browsers installed.

```bash
npm install
npx playwright install chromium firefox
npm run test:a11y
```

The Playwright `webServer` config (`playwright.config.ts`) starts a static server over `public/` on port `4173`. Each test navigates to a screen, clicks its nav tab, runs `AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa', 'wcag22a', 'wcag22aa']).analyze()`, and asserts zero violations.

To inspect the HTML report after a run:

```bash
npx playwright show-report
```

## Allowlist

The allowlist lives at `tests/e2e/a11y/axe-allowlist.json`:

```json
{
  "ignored_rules": []
}
```

It must stay empty by default. Adding a rule is a deliberate, reviewed exception — not a workaround.

### How to add a rule to the allowlist

1. Confirm the violation is real and that fixing it now is genuinely blocked (e.g., the offending markup ships from a third-party CDN you do not control).
2. Open a tracking issue describing the rule, the affected screen(s), and the planned remediation. The issue is required — do not allowlist anything without one.
3. Add the rule id to `ignored_rules` with a `TODO(<issue-number>)` comment in the surrounding PR description, and link the issue.

Example:

```json
{
  "ignored_rules": [
    "color-contrast"
  ]
}
```

PR description must include:

```
TODO(#NNN): re-enable axe rule "color-contrast" once <screen> is reskinned.
```

The reviewer rejects any allowlist change that lacks a linked issue and a stated remediation owner.

## Adding a new screen

When a new top-level dashboard screen lands:

1. Add an entry to the `SCREENS` array in `tests/e2e/a11y/axe.spec.ts` (`{ id, tab }`).
2. Run `npm run test:a11y` locally and fix any violations before merging.

## CI

The axe scan runs as part of the Playwright job. Build fails on any AA violation. The HTML report is uploaded as a CI artifact for triage.
