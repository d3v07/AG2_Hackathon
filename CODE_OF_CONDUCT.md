# Contributor Code of Conduct

## Purpose

Concord is a developer tool for validating and repairing AG2 multi-agent workflows. The project should stay useful, direct, and evidence-driven. This code of conduct sets the baseline for how contributors work together in issues, pull requests, reviews, discussions, and any project-maintained communication space.

## Expected behavior

Participants are expected to:

- Be respectful and professional, especially when disagreeing.
- Critique code, design, tests, and product tradeoffs without attacking people.
- Prefer concrete evidence: logs, screenshots, failing tests, traces, file references, and reproducible steps.
- Keep discussions on the project goal: contract checking, violation attribution, repair patches, validation, persistence, and product quality.
- Respect boundaries around private data, credentials, customer traces, and unreleased work.
- Help newcomers understand the repo without lowering the engineering bar.

## Unacceptable behavior

The following behavior is not acceptable:

- Harassment, intimidation, threats, or sustained disruption.
- Personal attacks, insults, or demeaning language.
- Discriminatory language or conduct based on identity, background, location, religion, age, disability, or experience level.
- Publishing private communications, secrets, credentials, trace data, or security details without permission.
- Repeatedly derailing technical work after maintainers have made a scope decision.
- Using project spaces to spam, advertise unrelated work, or solicit unrelated services.

## Scope

This code applies in all project spaces, including GitHub issues, pull requests, discussions, documentation, examples, and maintainer-run communication channels. It also applies when someone represents the project in public.

## Reporting

If you experience or observe unacceptable behavior, report it to a project maintainer. If you already have a private maintainer contact, use that. If you do not, open a minimal GitHub issue asking for maintainer contact and avoid including sensitive personal details in public.

Security vulnerabilities should be reported through the process in [SECURITY.md](SECURITY.md), not through public issues.

## Enforcement

Maintainers may take action to protect the project and its contributors. Possible actions include:

- Asking for clarification or a change in tone.
- Editing or deleting comments that violate this code.
- Locking discussions that are no longer productive.
- Temporarily or permanently blocking participation.

Enforcement should be proportional, consistent, and focused on keeping the project usable.
